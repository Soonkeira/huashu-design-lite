# 复杂度路由行为测试报告 · 101–104

测试日期：2026-09-21
被测文本：`SKILL.md` + `references/`（安装副本 `~/.agents/skills/huashu-design-lite/`，与仓库逐字节一致）

## 测试方法

四个独立 agent，每个只收到一个用户需求，被要求回答"你会怎么做"，并逐字引用 SKILL.md 原文作为证据。

- **只读**：禁止创建/修改任何文件。
- **防泄漏**：允许读的路径只有安装副本目录；**严禁**读取本仓库（`test-prompts.json` 是答案库）；禁止联网搜索该 skill。
- **判行为不判词汇**：不看 agent 是否复述了模式名，看它给出的方向数、问题数、是否停轮是否与路由表一致。
- 同一模型首次阅读该 skill，因此测的是"文本本身能否把 agent 推上正确路径"，而不是"我是否记得规则"。

## 结果总览

| 用例 | 需求 | 预期 | 实测 | 结论 |
|---|---|---|---|---|
| 101 | 把博客文章页正文加宽、移动端别溢出 | FAST，直接改 | FAST，0 方向 / 0 提问 / 不停轮 | ✅ |

## 101 · FAST

**判定**：FAST。**产出 0 个方向（1 版实现）**，**提问 0 个**，不为选方向停轮。

逐字引用的证据：

- `SKILL.md:67-69`「- 已有页面/设计上的局部修改 / - 调整间距、留白、字号、颜色、对齐、组件样式 / - 修复 responsive / overflow / clipping」
- `SKILL.md:57`「### 设计复杂度路由（所有任务先执行）」
- `SKILL.md:139`「不要因为任务属于"设计"就自动升级到 FULL。」
- `SKILL.md:75-76`「- 不进入三方向流程 / - 不生成 design-demos」
- `SKILL.md:78`「- 没有真正阻塞项时不提澄清问题」
- `SKILL.md:335`「只有「存在值得用户决策的设计分歧」时，才生成多个方向。」

附带发现（agent 自行指出）：跳过方向门不等于跳过 Gate 文件——`SKILL.md:543`「跳过时在本文件记用户原话/迭代来源（**跳过≠可以不写文件**）」。

## 102 · STANDARD

**判定**：STANDARD（默认模式）。**2 个方向**，每个为 1 个完整 HTML + 截图；**最多 2 个问题**（一轮批量）；**停轮等选**，并把选择原话写入 `direction-approved.md`。**无任何字数指标。**

逐字引用的证据：

- `SKILL.md:86`「默认模式。」/ `SKILL.md:90`「- Homepage redesign」（STANDARD 适用范围字面命中）
- `SKILL.md:139`「不要因为任务属于"设计"就自动升级到 FULL。」
- `SKILL.md:100`「- 默认生成 2 个明显不同的真实视觉方向」
- `SKILL.md:337`「数量按 Design Mode：FULL 3 / STANDARD 2」
- `SKILL.md:418`「（数量按 Design Mode：FULL 三套全跑 / STANDARD 跑其中两套）」
- `SKILL.md:348`「问题数上限按 Design Mode，与路由表一致：FULL 一次最多 3 个 / STANDARD 一次最多 2 个」
- `references/workflow.md:7`「STANDARD 最多提出 2 个真正影响设计的问题，清单里的其余项自己按 best judgment 补 assumption（标 assumption），不要一次性甩 10 个问题给用户」

**关于篇幅（本项为本次改动的重点验证）**——agent 被追问"重述和 spec 大概多长、有没有字数要求"，回答「**没有任何字数/字符数指标**」，并给出：

- `SKILL.md:360`「**Phase 2 · 顾问式重述**（把需求真正嚼透，不是敷衍一句——篇幅按任务复杂度决定，**不设机械字数目标**）」
- `SKILL.md:361`「以「基于这个理解，我**直接做几个不同方向的真实版本给你看**」结尾……❌ 不要以「你想选哪个方向？」结尾」
- `SKILL.md:368-380`「使用 compact spec，控制在足够明确但不过度展开的程度」……「**每项 1-3 行即可。禁止为了满足长度要求写重复性设计散文。**」

结论：Phase 2「≥200 字」删除后，STANDARD 不再产生机械长篇重述；唯一的量化约束是 compact spec「每项 1-3 行」。

该 agent 自行标注的冲突：`SKILL.md:197`「给 3 个差异化方向」与模式分档的 2 冲突，采信 2（理由：`SKILL.md:337` 是专门定义"数量"的条款且自述"按 Design Mode"）。

## 103 · FULL

**判定**：FULL。**3 个方向**，两种产出形态分别定义：官网每方向 1 个完整 HTML + 截图，影片每方向 1 张方向板（明确不是三支成片）。**一轮最多 3 个问题** + 同批参考索要清单。**停轮等选**（含无人值守会话），落盘 `direction-approved.md`。**事实核查 + 品牌资产验证均执行**。

逐字引用的证据：

- `SKILL.md:111-113`「- 高价值正式官网 / - 正式产品发布页 / - Launch Film / Campaign」（FULL 适用范围字面命中）

- `SKILL.md:121-126`「三方向真实视觉」「完整设计 spec」「用户选择 Gate」「多轮视觉验证」
- `SKILL.md:337-340`「多方向初稿形态（按产出类型定义……数量按 Design Mode：FULL 3 / STANDARD 2）」/「网页 / 信息图 / 原型 → 每方向 1 个完整 HTML + 截图」/「**动画 / 宣传片 → 每方向 1 张「方向板」**……❌ 不是三支成片（成本失控），✅ 但必须是渲出来的画面不是嘴说」

## 104 · 显式 override（本次新增，重点用例）

**判定**：任务本身 = **FULL**；加用户那句话后执行 = **FAST**；**产出 1 版**，**不停轮等选方向**；**事实核查与品牌资产验证不豁免**。

先判 FULL 的证据：

- `SKILL.md:111`「- 高价值正式官网」/ `SKILL.md:112`「- 正式产品发布页」

降为 FAST 的证据：

- `SKILL.md:130`「用户的显式指令优先于自动判断：」
- `SKILL.md:135`「- 「直接做，不用出方向」→ FAST」
- `SKILL.md:71`「- 用户提供了明确参考，并要求直接照该方向实现」（FAST 适用范围）
- `SKILL.md:327`「- 用户明确说「直接做」「不用出方案」」（「直接跳过方向探索」清单）
- `SKILL.md:157`「若用户同时说「就按这个方向直接做」，则降为 FAST 照做。」
- `SKILL.md:151`「服从显式 Design Mode override（`/design fast`、「直接做、不出方向」→ 降为 FAST 照做，不硬门）」（连 launch film 这种最强 FULL 场景也写明可从属）
- `SKILL.md:700`「FAST：始终单方案直接执行。」

**关键点**——agent 给的降级理由不是"用用户指令覆盖规则"，而是**规则自身预设的例外**：

- `SKILL.md:564`「FULL 级任务（品牌从零/正式发布/宣传片）仍应出方向——**仅当用户明说「别出多版/一版就行」才降为单方案**，并在 `direction-approved.md` 记用户原话」

本需求的「正式发布」正是括号内的类别，用户「不要出多个方案」正是括号内的豁免条件，因此属于规则的既有出口，而非套用外部指令。

**override 的边界**（agent 明确保留，未被豁免）：

- `SKILL.md:80`「- 涉及真实品牌/产品/数据时仍执行事实与资产验证」（FAST 行为清单内）
- `SKILL.md:159`「## 核心原则 #0 · 事实验证先于假设（优先级最高，凌驾所有其他流程）」
- `SKILL.md:203`「Fallback 决定的是「用什么视觉风格」，**不豁免「取齐具名产品的 logo」**。两件事并行，不是二选一。」
- `SKILL.md:546`「**Runtime 能力降级不豁免 gate 文件**」
- `SKILL.md:706-709`「无论如何降级，都不得牺牲：」……「- 品牌资产真实性」

即：override 只关掉方向探索，不关掉正确性。

## agent 自行标注的规则缺口（已知，本次未修改）

以下两处是四个 agent 唯一需要"自己判断"而非"读规则"的地方。行为结论正确，但依据是推断而非条款，记录备查，本次不修改。

**① FAST 与主流程 🛑 检查点的关系未写死。**
101 与 104 两个 agent 各自独立指出：FAST 条款只说「- 直接实现」(`SKILL.md:81`)，但主流程的 `SKILL.md:505`「🛑 **检查点3：五问答案 + 系统口头说出来等用户点头，再动手写代码**」、`SKILL.md:508`「🛑 **检查点4：尽早show给用户（哪怕只是灰色方块+标签），等反馈再写组件**」、`SKILL.md:534`「碰到🛑就停下……然后真的**等**」从未显式豁免 FAST。两个 agent 都自行推断"检查点绑定在新建环节（再动手写代码 / 再写组件），本次是改现有页"因而未停轮。
→ 影响：若某次 FAST 任务卡在等批准，根因在此。

**② 一个任务同时有两种产出形态时，方向数如何合并未写。**
`SKILL.md:337` 说初稿形态「按产出类型定义」，但未规定官网 + 影片并存时应为"3 个方向各出两种形态"还是"共 6 件"。
→ 103 的 agent 自选读法：**3 个方向 × 2 形态**（3 个 HTML + 3 张方向板），并建议在澄清问题里就此确认。

**③ 核心哲学中的 "3+" 残留（已知保留，非缺口）。**
`SKILL.md:197`「从 HTML 原生 60 种风格库…里给 3 个差异化方向」、`SKILL.md:232`「给3+个变体」、`references/workflow.md:33`「想要几种variations？（推荐3+）」。三个 agent 都正确判定其被 Design Mode 覆盖，判定理由一致（路由节自称"所有任务先执行"，是上位闸门）。
→ 结论：这几处字眼不影响路由行为，按定案保留，不作为回归信号。
